## Decisions & Learnings
- **NaN policy.** The oracle compares NaN by class only (MPFR has no NaN
  sign; IEEE-754 does not prescribe one for domain errors). Engine-vs-engine
  comparison stays exact bits and passes. This contradicts an over-literal
  reading of the frozen plan and is recorded as amendment 1 instead of
  forcing 86 correct CORE-MATH NaN signs to fail.
- **Historical glibc is not correctly rounded.** 126 non-NaN cases where
  system libm differs from the oracle are exactly the cases where CORE-MATH
  matches a 4096-bit MPFR evaluation. The system axis stays recorded but is
  not oracle-enforced.
- **Engagement evidence matters.** The core_math state corpus is
  bit-identical to system_libm on these eight static levels, so the state
  capture alone cannot prove which backend ran. Explicit identity probes and
  hard-fail preflights were added; 3 of 4 probes differ.
- **Performance is a real cost in Lua.** Trig/pow/log are 1.3-2.8x slower
  per call through the FFI; `atan2`, `sqrt`, and `mod` are at or below
  system cost. The stride-20 candidate sweep is ~21% slower with 24-36%
  run-to-run variation, so WP-F reports direction, not a precise ratio, and
  makes no adoption claim.
- **Preserve unrelated work.** The dev tree had a pre-existing
  `ball_ball_restitution = 0.7` edit. The WP-E control temporarily needed
  the pinned 0.8; the edit was preserved in `tmp` and restored, and the
  trace script now aborts on a config mismatch instead of silently
  reverting.
- **Independent verification caught real gaps.** A verifier reproduced
  12/12 oracle re-derivations and tamper detection, disputed the NaN-sign
  wording, found the parity per-record diagnosis gap, and asked for explicit
  raw-fixture/checkpoint controls; all three were fixed or ruled on.

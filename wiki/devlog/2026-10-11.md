## Decisions & Learnings
- **Trace backend identity is scope metadata.** The Julia trace header writes
  `math_backend` only when the DetMath backend is not `system_libm`
  (`DetMath.math_backend_identity()`). `tools/compare_traces.py` records the
  block and never counts it as a simulation difference. Default `system_libm`
  traces stay byte-identical between Lua and Julia.
- **The benchmark needs its own workload catalog.** The pinned
  `harness/workloads.lua` cannot load the untracked mustache level. The
  additive `--workloads FILE` option and `fixtures/mustache/workloads.lua`
  keep the pinned catalog and the M0/M1 sweeps unchanged. `--artifact-dir`
  does the same for the level artifact.
- **Spawn coverage lives in the traces.** The Lua raw sweep format does not
  emit `spawned`, so the sweep comparison covers 16 shared fields. The
  multiball trace fixture covers spawn behavior instead.
- **Snapshots are comparison artifacts.** The durable corpus stays
  snapshot-free to bound repository size. The comparator still requires full
  per-step snapshot coverage on both sides.
- **Speedup claims stay caveated.** The 1.95x same-core figure compares one
  post-warmup Julia pass with a Lua repeat=2 mean. Rates vary between runs,
  so the report labels the ratio indicative.

## Post-Review Fixes
- **The engine owns shot completion.** `finalize_step!` sets `eng.shot_done`
  at the `shot_end_pending` transition; `on_turn_end` is a notification only.
  Previously `run_shot!` with the default `ShotCallbacks()` kept simulating an
  empty board and emitted `shot_completed` every step. Regression test:
  `test_engine.jl` "default callbacks: the engine owns shot completion"
  (mustache aim 900: 975 steps, one `shot_completed`, `clear_queue === nothing`).
- **The sweep gate requires its fields.** `scripts/compare_m3_sweeps.py`
  rejects (exit 2) any row missing a shared result field on either side; only
  `spawned` stays exempt because the Lua harness raw never emits it.
  `scripts/test_compare_m3_sweeps.sh` covers clean, missing-field, and
  value-mismatch corpora; it runs as step 8/8 of `make check`.

## Update (2026-10-11): engine/worker-local allocation optimization

### Progress Summary
- An allocation optimization reduces the per-shot heap allocation and the
  per-shot latency of the M3 shot engine. The durable report is
  `results/allocation-deathstar-6d09319-candidate.json`.
- The candidate is an uncommitted worktree snapshot on baseline commit
  `6d09319`, measured on deathstar with Julia 1.12.6 and the default
  `system_libm` backend.
- The engine reuses worker-local scratch across shots and candidates.
  Physics contacts use immutable typed payloads. The serialized trace
  format does not change.

### Changes Made
- **Engine scratch.** `julia/PeggleSim/src/engine.jl` adds `ShotScratch`
  (physics context, contact-reduction containers, style/slide lookup
  dictionaries, ball buffers). `reset_shot_engine!` empties the pools and
  rebinds the physics context to the restored ball vector.
- **Physics.** `julia/PeggleSim/src/physics.jl` keeps one engine-owned
  `PhysicsContext` with reusable `IdDict` frame maps and a frame pool. The
  graze buffer and the frame maps reset without a reallocation.
- **Typed payloads.** `julia/PeggleSim/src/contact_payloads.jl` (new)
  defines the immutable `ContactLine` and `ContactPayload` types.
  `events.jl` stores these payloads directly. It removes the per-contact
  line-metadata dictionaries and the recursive payload copying. Commands
  still copy their payloads, so the serialized trace format is unchanged.
- **Trackers.** `ball_state.jl`, `slide_inversion.jl`, and `style_shots.jl`
  reuse their per-step buffers.
- **Tools and tests.** New: `scripts/allocation_bench.jl`,
  `scripts/allocation_remote.sh`, `scripts/allocation_validate.py`,
  `julia/PeggleSim/test/test_shot_scratch.jl`, and
  `julia/PeggleSim/test/test_contact_payloads.jl`.

### Decisions & Learnings
- **Order stays deterministic.** Contact groups use tuple keys in first-seen
  order, pool slots are reused in that order, and scoring keeps the raw
  contact order. The trace bytes do not change.
- **Measurement method.** The harness warms the engine, then measures a
  single-thread `reset`+`launch`+`run` with tracing disabled and extraction
  excluded. It records 15 samples per aim and reports the median. Timing is
  warmed single-shot on a shared host, not sustained throughput.
- **Aim 900:** 4,341,056 bytes to 1,361,248 bytes (68.64% fewer), median
  8.53 ms to 5.82 ms (about 1.47× faster).
- **Aim 570:** 69,226,960 bytes to 8,915,760 bytes (87.12% fewer), median
  187.40 ms to 72.74 ms (about 2.58× faster).
- **M4 remains open.** The engine still allocates per shot, so this work
  does not meet the zero-allocation warm-stepping target.

### Verification
- Package tests: 5,608/5,608 pass. The extended
  `test_shot_scratch.jl` passes 98/98.
- Traces: the five mustache fixtures are byte-identical to the baseline
  and to the committed Lua goldens.
- Sweeps: stride-20 rows at 1, 2, and 4 threads are identical between
  baseline and candidate.
- Reference: `make verify` reports 133/133 files OK before and after.

### Next Steps

## Update (2026-10-11): IdDict scratch reset allocation fix

### Progress Summary
- The scratch `IdDict` resets in the shot engine and the physics context are
  now `Dict` resets. The fix removes 1,051,776 B at aim 900, which is 77.3%
  of the residual left by the engine scratch optimization.
- Durable report: `results/allocation-deathstar-6d09319-idict.json`.
- Root cause: `empty!(::IdDict)` on Julia 1.12.6 discards the capacity and
  reallocates 288 B. Three reset sites run per physics step
  (`engine.jl:64/66`, `physics.jl:193`). They allocate 1,152 B per step at
  aim 900.

### Changes Made
- `engine.jl`: `ContactReductionScratch.suppressed_pool` and `scored` change
  from `IdDict` to `Dict`. The constructor literals and the pool `push!` site
  change too.
- `physics.jl`: `PhysicsContext.ball_frame` changes from `IdDict` to `Dict`.
- No other source, test, or script file differs from the prior candidate.

### Decisions & Learnings
- **Zero-cost reset.** `empty!(::Dict)` allocates 0 B for a warmed table.
  `empty!(::IdDict)` discards the capacity, so the next refill regrows it.
- **Identity semantics hold.** `Dict` uses the same mutable-struct identity
  keys. The micro-tests pass after mutation, after `empty!` plus reinsert,
  and against a `deepcopy` with equal fields.
- **Iteration order.** No order contract applies to the three scratch
  tables. The trace bytes do not change.
- **Aim 900:** 1,361,248 bytes to 309,472 bytes. Median 5.81 ms to 5.75 ms.
- **Aim 570:** 8,915,760 bytes to 7,088,688 bytes. Median 72.57 ms to
  72.42 ms.
- **Known remaining sources.** The checkpoint `restore!` path (~27.8 KB per
  reset) and the trace encoder stay unfixed (allocation hunt report:
  `tmp/allocation-hunt/REPORT.md`). M4 stays open.

### Verification
- Package tests: 5,608/5,608 pass. `make verify`: 133/133 files OK before
  and after.
- Traces: the five mustache fixtures are byte-identical to the baseline
  (plain and snapshot-enabled) and to the committed Lua goldens.
- Sweeps: stride-20 rows are identical at 1, 2, and 4 threads and against
  the baseline.
- Results: all measured results are identical across the baseline, prior
  candidate, and fixed candidate.
- Profile.Allocs (trace disabled, aim 900): 288,611 B, and the three reset
  sites are absent.

### Next Steps
- M4: zero-allocation warm stepping. The measured remaining sources are the
  checkpoint `restore!` path and the trace encoder.

## ribbon_waves v2 — smooth ribbons and correct ball/peg scale

> **Superseded by v3** later on 2026-10-22. v2 still represented each ribbon as
> 46 annular bricks with 1–2 px seam insets; the user rejected that as "a bunch
> of distinct pegs" and required one continuous slide per ribbon. See
> [Correction: single continuous slides (v3)](#correction-single-continuous-slides-v3)
> below.

The user rejected the 2026-10-21 [ribbon_waves](2026-10-21.md) attempt:
fitting each brick independently to `peg_mask.png` made the ribbons read as
disconnected pieces, and the level was authored at native screenshot scale
so the pegs were too large for the 6 px ball. v2 fixes both.

### What changed

- **One smooth centerline per ribbon.** Five 400-point centreline splines
  are fitted to the segmented bands; the 46 real brick boundaries split each
  spline into arcs that share their boundary point exactly (max gap
  ~5e-12 px). No per-brick raster fitting.
- **Correct scale.** `s = 10/22`, anchored at the shooter `(772.5, 50)`:
  world 702.2727×613.1818, peg r=10, ball r=6 (ratio 0.60, screenshot
  14.5/24 = 0.604).
- **Colors are non-gating.** `type_counts = blue 73 / green 1 / purple 0 /
  red 25`; the engine reassigns colors from the seeded pool. No authored
  purple and no color-matched permutation.
- **Smooth rendering.** `Peg.new_annular` gained an optional 8th `segments`
  argument; the 46 ribbon pieces use 16. The default path is byte-identical
  (mustache re-export unchanged, engine suite 480 passed).
- **Playable seams.** An adaptive per-seam angular inset (cap 0.02 rad,
  mean 0.006758) clears cap overlaps; `check_level` is 0 ERROR / 0 WARN.

### Results

- Mask: cleaned IoU **0.937084** (per ribbon 0.9059 / 0.8684 / 0.9160 /
  0.9132 / 0.9102; circles 0.9948). The 0.97 fidelity reference is not
  reached; the residual is the constant-thickness/one-arc representation,
  not speckle. Reaching it would require the per-brick fitting the user
  rejected.
- Corpus: 3 traces (`center` 966, `left_wall` 262, `ribbon` 1,920 events)
  replay byte-exactly in Julia with `segments = 16`; full `make julia-test`
  **6,737 passed / 0 failed**; `capture_ribbon_waves.sh --check` passes;
  `capture_m3_mustache.sh --check` remains 5/5.
- Artifacts: geometry `b3e3f615…`, level artifact `4f2ef7c2…`, config
  `170487a4…`.

## Correction: single continuous slides (v3)

**2026-10-22, 17:13 CEST.** The user rejected v2's 46-brick representation:
the ribbons still looked like a bunch of distinct pegs. The requirement is
explicit:

> each ribbon must be a single slide, a single curve that contains all the
> pegs, as in the squiggly circle level.

### What changed

- **Five continuous lines.** Each ribbon is now exactly one `Path.new` (10
  cubic Hermite segments, open; native in the geometry, affine-mapped to
  world in the level) followed by one `Lines.generate` zero-gap annular line:
  `wave_1`..`wave_5`. This is the same primitive as
  [squiggly_circle.lua](../../../peggle_evolved/src/levels/squiggly_circle.lua)
  and [mustache.lua](../../../peggle_evolved/src/levels/mustache.lua); no new
  slide entity was needed.
- **Zero-gap metadata.** 114 generated annular pegs: counts 20/20/26/28/20.
  Every one has `line.gap = 0`, `line.closed = false`, contiguous
  `line.index` 1..count, and `shape.segments = 16`. The 53 circles carry no
  line; total is 167 pegs. The level now contains zero direct
  `Peg.new_annular` calls and no adaptive seam inset.
- **Engine.** [src/systems/lines.lua](../../../peggle_evolved/src/systems/lines.lua)
  accepts optional `spec.peg.segments` for annular lines and forwards it to
  `Peg.new_annular`; `nil` preserves the historical heuristic.
  `Peg.new_annular` itself is unchanged in v3. Level authoring uses
  `segments = 16`, `curve_tolerance = 1.0`, `max_length = 40.0`, `gap = 0`.
- **Path model.** `cubic-hermite-lsq-spline-v1`, 10 cubic Hermite segments per
  ribbon, 8 px end trim, LSQ knot spacing 35 px (wave_2 60 px). Fit RMS
  0.356/1.798/0.315/0.325/0.225 px; max 1.284/7.306/1.146/1.125/0.828 px;
  min curvature radius 30.16/27.66/73.78/72.80/52.32 px (native).
- **Counts.** Authored `type_counts = red 25 / green 1 / purple 0`; blue
  derived 141. `check_level` reports 167 pegs (53 circles, 114 annular),
  ERRORS 0, WARNINGS 0, PASS.
- **Fixtures.** bench, one ball, `fell_out`: `center` aim 900, 312 steps,
  21 pegs, 13,860 pts, no style; `left_wall` aim 1800, 658 steps, 20 pegs,
  7,600 pts, no style; `ribbon` aim 120, 434 steps, 41 pegs, 47,640 pts,
  `slide` x1. The `ribbon` shot can now award SLIDE because line metadata is
  present (v2 could not).

### Results

- **Mask:** cleaned IoU **0.944666** (P 0.964395, R 0.978803); bands
  0.930223 / 0.885778 / 0.924359 / 0.918036 / 0.922391; raw IoU 0.932317.
  This is *better* than v2's 0.937084 despite removing the seams: the smooth
  path ignores the seam notches and end-cap artifacts. The 0.97/0.95
  fidelity reference is still not reached and is not claimed; the residual is
  constant thickness, end caps, and smooth-path fit, not seams.
- **Engine suite:** 483 passed / 0 failed; mustache export byte-identical

- **Full Julia suite:** 8,292 / 8,292.
- **Focused Julia test:** 2,675 / 2,675. It asserts the five line groups,
  `segments = 16`, the path contract, and byte-exact Lua traces.
- **Artifacts:** level sha256 `089d2c83...` (21,406 B); geometry

# Dev Log - 2026-10-03

## Progress Summary
- Implemented M0 of the Julia port plan: froze the Lua reference, defined the
  candidate workload and decision boundary, built a sweep harness, and
  measured the Lua baseline that later milestones are compared against.
- Created the `julia_clone` repository (initial commits `c8dbddb`, `7894c37`)
  with the pinned reference, harness, scripts, and results.
- Adopted the parent project's wiki conventions: `docs/` was migrated into
  `wiki/context/` and `wiki/benchmarks/`, and this devlog starts the
  `wiki/devlog/` series.

## Changes Made
- `reference/` - vendored `peggle_evolved@d17f6e7` (133 files) with `PIN.md`
  and `files.sha256`; `scripts/verify_reference.sh` checks the tree.
- `harness/` - LÖVE app that sweeps the legal aim grid from the ready-to-aim
  boundary. Per candidate it times `init` (engine + level setup), `reset`
  (turn reset), `sim` (launch + fixed steps), `extract`, and `output`. It
  validates grid identity, runs determinism spot checks, supports warmup and
  repeat counts, multiball launches, optional end-of-turn clearing, and
  writes summary JSON plus optional per-candidate JSONL.
- `harness/workloads.lua` - seven static workloads covering circles, mixed
  circles, rectangles/annular/lines, dense annular, and two multiball cases.
- `scripts/` - `run_baseline.sh` (metadata capture + run), `love.sh`
  (headless display wrapper), `verify_reference.sh`, `render_summary.py`.
- `wiki/context/` - `reference.md`, `workload.md`, `inventory.md`.
- `wiki/benchmarks/baseline-metrics.md` - the measured baseline and the
  continuing-metric protocol.
- `wiki/templates/` - devlog and ADR templates copied from the parent project.

## Decisions & Learnings
- **Reference is committed `d17f6e7`, not the working tree.** The Lua tree had
  uncommitted edits in `path.lua` and `physics.lua`; a reference must be
  reconstructible from a commit, so they are excluded. If committed later, the
  pin advances and all baselines and fixtures are re-captured.
- **The action space is 1801 aim indices, not 1800.** The grid comes from the
  snapping function (`floor(n*1800 + 0.5)/1800`), which reaches index 1800 at
  the arc endpoint. The harness proves `getSnappedAimAngle(angle(i)) ==
  angle(i)` for all indices before every run.
- **Default shot end is the bench boundary** (no launched ball remains),
  keeping M0 comparable with existing Lua tools. `--clearing on` measures
  through end-of-turn clearing to the next ready-to-aim boundary; that is the
  M4 completion rule.
- **Per-candidate `init` dominates dense levels.** On `annular_dense`,
  rebuilding the level (including regenerating 192 annular pegs) costs 81 ms
  at p50 against 5.5 ms of simulation. The M2 checkpoint contract removes
  this cost: about 15x potential throughput on that workload. This is the
  strongest measured justification for the checkpoint/reset design.
- **Simulation cost is long-tailed.** On `lines_rect_annular`, `sim` p50 is
  2.8 ms but p90 is 22.5 ms. Median-only reporting would hide the cost of
  slide-heavy shots.
- **The baseline host throttles under sustained load.** Repeats 1 to 3 slowed
  from 11.2 to 7.5 candidates/s on `annular_dense`, with the CPU at 94.5 C
  while the desktop session also ran. Determinism spot checks passed in every
  workload, so this is thermal/contention variance, not engine
  nondeterminism. Dedicated benchmark hardware remains deferred, per plan.
- **Replay serialization stays in the baseline.** `launchBalls` serializes
  the rolling capture in the real game; removing it silently would credit the
  port for less work. `--no-replay-serialize` exists for experiments only.
- **Documentation now lives under `wiki/`**, matching the parent repository,
  with `tmp/` (or the parent `temp/`) reserved for ephemeral notes.

- `wiki/context/interchange.md`, `wiki/context/fixtures.md`; quickstart,

## Decisions & Learnings
- **The v1 level artifact is the post-load, pre-color board.** Running the
  engine's own load pipeline and recording the surviving pegs means M2 does
  not need to re-port boundary filtering to reproduce the authoritative
  geometry. Effective `type_counts` (including derived `blue`) and the level
  seed are the color-assignment inputs.
- **Peg `type` is normalized through the engine's `typeDef` fallback.**
  `circle_level.lua` passes a numeric third argument intended as a radius
  (`Peg.new(62.0, 71.67, 11.66)`); the engine treats it as an unknown type and
  uses the default, with radius falling back to 10. The artifact records the
  resolved type, so the schema always sees a valid enum.
- **Motion is rejected, never downgraded.** The legacy dumper converted
  `path_fn` circuits to `kind = "unknown"` with a warning; the v1 exporter
  exits 2 with a specific reason. The static set is the eight levels with no
  circuits and no `peg.motion`.
- **The "42-case matrix" does not exist.** It was a planning placeholder in
  the strategy note; M1 replaced it with a mechanism-oriented matrix
  (`wiki/context/fixtures.md` §1) whose every acceptance category maps to at
  least one fixture.
- **Capture is byte-reproducible by construction.** Fixture records contain no
  timestamps or host data; re-capture under the pinned revision is
  byte-identical, verified by `scripts/capture_fixtures.sh --check`.
- **Traces omit per-step snapshots.** `include_snapshot = false` keeps the
  event/command stream (what cross-engine comparison needs first) at 1.1 MiB
  for six fixtures; snapshots remain available when M4 needs them.
- **Graze boundary is strict.** Probing 0.25/0.50/0.75 px past tangent shows a
  graze at 0.25, no event at exactly `graze_tolerance = 0.5`, and no event at
  0.75. Fixtures pin that behavior rather than assuming inclusivity.
- **Natural shot discoveries:** `long_shot` index 1736 awards long shot,
  triggers fever (its only red), and spawns two power balls; the `slide`
  straight drop (index 900) grazes all 38 rail pegs and awards slide; clean
  `bucket_catch` is `circle_level` index 61.

# Dev Log - 2026-10-03 — M1 review fixes

## Progress Summary
- Fixed the five findings from the M1 acceptance review: verifier overwrite,
  empty-object codec, checkpoint contract, two mislabeled boundary fixtures,
  and full-ring preview centers. All M1 acceptance commands pass.

## Changes Made
- `tools/canonical_json.lua` — explicit container kinds. `CanonicalJSON.object`/
  `array` mark tables; the decoder tags every decoded container; an unmarked
  empty table is now a hard error instead of silently encoding as `[]`.
  `tools/canonical_json_test.lua` (new) is step 1 of `make check`.
  `fixtures/expected/*.json` were re-captured: zero-style shots now carry
  `"styles":{}`.
- `harness/main.lua` — `--fixtures --check` no longer writes to the reference
  corpus. It captures traces to temporary files, verifies the expected record's
  trace hash and event count, byte-compares the regenerated trace with the
  reference trace, and only then compares records. New `--fixtures-traces DIR`.
  `scripts/test_fixture_check.sh` (new) proves a corrupted trace fails
  verification and is left untouched; `make check-all` runs it.
- `fixtures/scenarios.lua` — `probe_rectangle_corner_rotated` now starts clear
  of the expanded rectangle and sweeps the local corner circle (single
  `sweep` at TOI 0.9997, impact on the corner); `probe_annular_cap_crossing`
  now approaches the start cap perpendicularly from outside the angular span
  (single `sweep` at TOI 0.71 on the cap plane at radius 44.1). Both probes
  assert their intended mechanism before the record is accepted.
- `schemas/checkpoint.v1.schema.json` + `scripts/validate_interchange.py` —
  the checkpoint contract now advertises `ready_to_aim` only and specifies
  permanent ball-ID allocation (`next_ball_id`/`used_ball_ids`), bucket
  `x`/`phase`, clearing state, fever buckets, full tracker structure, and the
  match layer (players/inventories, shared bucket counter). Cross-field
  invariants reject degenerate records. New representative example
  `schemas/examples/checkpoint.v1.example.json`.
- `scripts/validate_interchange.py` — shot fixture results are now validated
  as a `peggle.shot_result`, so the zero-style `styles` object is enforced by
  the schema rather than only by the encoder.
- `scripts/render_level_svg.py` — full annular rings use horizontal diametric
  arcs, so inner and outer circles share the peg center.

## Decisions & Learnings
- Ambiguous empty containers are rejected by construction; call sites state
  `{}` vs `[]` explicitly. This is the durable fix for the schema mismatch,
  not a one-off wrapper for `styles`.
- Verification is read-only by contract: re-capture is compared against the
  corpus, never merged into it. The negative test pins that behavior.
- Boundary fixtures must fail capture when the claimed contact does not
  happen, so a fixture can never be silently re-interpreted.
- Checkpoint v1 deliberately leaves mid-shot capture undefined; supporting it
  would change the required continuation state and needs a version bump.

## Re-review fixes — checkpoint contract (second pass)
- `scripts/validate_interchange.py` no longer rejects
  `clearing.is_end_of_turn == true`. `Engine:resetTurn()` clears the queue
  and timer but not `clearingIsEndOfTurn` (core.lua:510-554, set at
  core.lua:1019, read only while the queue drains at core.lua:1059), so the
  flag is retained and inert while `active` is false. `active == false` and
  `timer == 0` are still required.
- `schemas/checkpoint.v1.schema.json` now requires all seven scoring and
  progress fields (`is_fever`, `current_multiplier`, `hit_counter`,
  `total_red_pegs`, `red_pegs_hit_amount`, `bonus_score`, `style_score`).
  Their descriptions state the reconstruction rules: cumulative progress is
  authoritative and serialized verbatim (hit pegs are removed by clearing, so
  it cannot be rebuilt from `engine.pegs`); `current_multiplier` and
  `is_fever` are derived by `Engine:updateMultiplier` (core.lua:306-320);
  `bonus_score`/`style_score` are per-turn accumulators that must be 0 at
  ready-to-aim (core.lua:544-545).
- `scripts/test_checkpoint_contract.sh` (new) mutates the example checkpoint
  into the post-turn state reproduced from `clearing_cascade`
  (`step_id=183`, `shot_id=1`, `hit_counter=6`, reds 2/10, retained
  `is_end_of_turn=true`) and requires it to validate; six negative cases
  require rejection (missing `hit_counter`, reds over total, multiplier
  mismatch, fever-flag mismatch, non-zero bonus/style). Wired into
  `scripts/check_interchange.sh` as step 5/5, so `make check` covers it
  without LÖVE.
- Docs corrected: `wiki/context/interchange.md` §5 no longer claims
  step/shot counters are always 0 at ready-to-aim (`setupLevel` resets
  `shot_id`, `launchBalls` increments it, `resetTurn` does not) and specifies
  the clearing retention and scoring reconstruction rules; `schemas/README.md`
  updated.
- Re-verified: `make verify` (133 files), `make check` and `make check-all`
  green (contract cases, 25 fixtures, negative verifier test), `make
  self-check` 0 mismatches, `make test` 475 passed.

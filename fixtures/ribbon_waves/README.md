# ribbon_waves fixture corpus (v3, world-scale single slides)

The `ribbon_waves` level is reconstructed from a Peggle Evolved screenshot:
53 circular pegs and five curved "ribbon" waves.

**User-facing correction (v3).** Each ribbon is **one smooth, continuous
zero-gap curve** — one `Lines.generate` line per ribbon — not a chain of
distinct bricks. This is the same primitive as `squiggly_circle` and
`mustache`: a `Path` of consecutive cubic Hermite segments is handed to
`Lines.generate`, which emits the annular pegs along it with `gap = 0`. The
level is **five continuous slides**, not 46 independent annular bricks. The
source geometry's `pieces` array (46 entries) is retained only as legacy
seam/colour diagnostics and is **not** the level's collision geometry.

The corpus is deliberately outside the pinned M1 interchange corpus; it is
captured from the `../peggle_evolved` dev tree, like `fixtures/mustache/`.
`make check-all` never re-captures it.

## Board

- **167 pegs** = **53 circles** (`r = 10` world) + **114 annular** pegs.
- **Five `Lines.generate` lines**, one per ribbon, with counts
  **`wave_1` 20, `wave_2` 20, `wave_3` 26, `wave_4` 28, `wave_5` 20**
  (total 114). Every annular peg carries line metadata with
  `closed = false`, `gap = 0`, and `index` running `1..count`; all five
  lines are open zero-gap slides.
- The level source makes **5 `Lines.generate` calls and 0 direct
  `Peg.new_annular` calls**. Line metadata lives on each annular peg
  (`line.id`, `line.index`, `line.count`, `line.closed`, `line.gap`); there
  is no separate top-level `lines` array in the artifact.
- All **114 annular pegs** are emitted with **`segments = 16`**. The engine's
  `Peg.new_annular` accepts an optional `segments` override, which
  `Lines.generate` now forwards from the authored `peg.segments = 16`.
  Four segments made the waves visibly faceted, so the ribbon pegs use 16.
  The default path is byte-identical for existing levels (mustache re-export
  unchanged).
- **No adaptive seam inset.** Adjacent pegs on a line share a full cap
  (`gap = 0`); the old v2 angular-clearance trim is gone.
- **Path contract.** Each ribbon has a `path` object with model
  `cubic-hermite-lsq-spline-v1`, **10 cubic Hermite segments**, `trim_px = 8`
  native px, and knot spacing **35 px except `wave_2` 60 px**. Fit RMS is
  **0.355742 / 1.797935 / 0.314809 / 0.325212 / 0.225308 px**; minimum
  curvature radius is **30.163175 / 27.662588 / 73.780060 / 72.797285 /
  52.324141 px**. The generator consumes this path and emits one
  `Lines.generate` line per ribbon.
- **`type_counts` (exported artifact): blue 141, green 1, purple 0, red 25**
  (sums to 167). `level_seed = 20261021`. The source geometry's legacy
  colour intent is blue 73 / green 1 / purple 0 / red 25; actual pegs are
  authored positionally (25 red + 1 green + 27 blue circles, all 114 annular
  blue) and the engine's `PegColors.init` reassigns every peg from the seeded
  pool at `setupLevel`. Positions, shapes and counts are the contract.
- Provenance: revision `da752257f613abbd209f1aa1acdd37a5f9be05f5`, tree
  `61278edc5467bf8399c24f4af0fcf36d75cac6a2`, config SHA-256
  `a17e60b43b1437510a59ba59c8791b27600a4b7fd7d56bc5f9c18d3e94f114d9`.

### Aim-direction note

The level grid is 0..1800 with 900 = straight down. In world coordinates
`x` grows right and the launch angle is
`pi/2 + (index/1800 - 0.5)*pi`, so **aim 0 launches toward +x (right wall)**
and **aim 1800 toward -x (left wall)**. The fixture id keeps the corpus
naming (`left_wall`) and uses aim 1800.

## Mask check

```bash
python3 scripts/check_ribbon_waves_mask.py
python3 scripts/check_ribbon_waves_mask.py --selftest   # 40/40
```

The stdlib-only checker loads the **exported artifact** (what the game and
Julia consume), inverts the world transform from
`source/ribbon_waves_geometry.json`, rasterizes the circles and analytic
annular sectors at 1545x1289 with 4x4 supersampling, and compares against
`reference/peg_mask.png`. Annular rasterization is independent of the
collision `segments`, so the `segments = 16` change does not move the mask
numbers.

The raw mask has black speckles and 1-4 px brick-seam gaps from the
screenshot. Cleaning is performed before the authoritative comparison:
8-connected components with area > 2000 are ribbon material (the 53 circle
components are 1517 px each and are left untouched), the ribbon material is
closed with a 5 px disk and each resulting band's holes are filled. Exactly
5 bands must result. Raw and cleaned results are both reported, with separate
diff images.

| Metric (cleaned, authoritative) | Value |
| --- | ---: |
| IoU | **0.944666** |
| Precision / recall | 0.964395 / 0.978803 |
| Artifact px / cleaned mask px | 222,554 / 219,278 |
| False positive / false negative px | 7,924 / 4,648 |
| Band 1 / 2 / 3 / 4 / 5 IoU | 0.930223 / 0.885778 / 0.924359 / 0.918036 / 0.922391 |
| Circles (raw mask, informational) | 53, mean = min = 0.994754 |
| Raw mask IoU (not gated) | 0.932317 (precision 0.951742, recall 0.978577) |

**Gates: overall IoU >= 0.92 and every ribbon >= 0.86.** These are
**regression floors, not a fidelity claim**. The accepted model is the v3
single-slide representation: one continuous zero-gap `Lines.generate` line
per ribbon, constant thickness and squared end caps. The artifact does **not**
open seam insets — the old adaptive seam inset is **GONE**, and adjacent pegs
share a full cap. The remaining gap to 0.97 is constant thickness + squared
end caps + smooth-path/end-trim residuals, not seam insets. The honest
cleaned IoU is **0.944666 overall / 0.885778-0.930223 per band**. The original
0.97/0.95 target is reported only as a fidelity reference; it is not a gate.
Geometry is never tuned to the raw speckles.

## Capture / check

```bash
scripts/capture_ribbon_waves.sh          # copy geometry, re-export, capture the corpus
scripts/capture_ribbon_waves.sh --check  # verify only; never writes the corpus
```

Capture mode:

1. copies `../level_segment/ribbon_waves_geometry.json` into `source/`;
2. reads the dev-tree revision/tree and `src/config.lua` SHA-256;
3. exports `artifact/ribbon_waves.v1.json` and `config.dev.v1.json` with
   `export_level.lua`/`export_config.lua --check`;
4. runs `scripts/check_ribbon_waves_mask.py` on the exported artifact,
   refreshing `mask_diff.png`, `mask_diff_raw.png`, `mask_metrics.json`;
5. runs the harness fixture mode with `--catalog`, `--fixtures-out`,
   `--fixtures-traces`, `--reference-dir ../peggle_evolved`,
   `--artifact-dir fixtures/ribbon_waves/artifact`, and resolved provenance.

Check mode re-exports both artifacts into a temporary directory and requires
byte identity, requires the source-geometry copy to match upstream, runs the
checker with temporary diff/metrics files, and runs the harness with
`--check` (records/traces are re-captured to temp files and compared). It
never writes the corpus. Expected tail:

## Julia test

`julia/PeggleSim/test/test_ribbon_waves.jl` is auto-included by the test
runner (`test_*.jl`); no `runtests.jl` edit is needed. Focused run:

```bash
julia --project=julia/PeggleSim -e \
  'using Test, JSON, PeggleSim; include("julia/PeggleSim/test/test_ribbon_waves.jl")'
```

It checks:

* the world transform pins (`scale`, shooter, vw/vh, peg r10, ball r6) and
  that the artifact virtual size matches;
* 53 CircleShape pegs and 114 AnnularShape pegs, ids 1..167;
* **the five line groups**: every annular peg carries line metadata whose
  `id` is one of `wave_1`..`wave_5`, `count` matches `20/20/26/28/20`,
  `index` runs `1..count`, `closed == false`, and `gap == 0`; every annular
  shape has `segments == 16`; every circle has `line === nothing`;
* `type_counts` sum == 167, `purple == 0`, `red == 25`, `green == 1`,
  `blue == 141`, and the per-peg colour counts match (the engine may assign
  colours freely; per-peg colours are not compared to the screenshot);
* every peg static (`base_x == x`, `base_y == y`), valid shapes
  (`0 <= r_in < r_out`, positive sweep <= 2*pi, `segments >= 4`), and
  in-bounds extents. For annular pegs the `(x, y)` is the arc's circle
  centre, which can legitimately lie outside the board, so the test bounds
  the sampled arc (`r_in`/`r_out` over 65 points), not that centre;
* **the `path` contract** from the pinned source geometry: model
  `cubic-hermite-lsq-spline-v1`, `segment_count == 10`, 10 contiguous cubic
  segments (`p1 == next p0`), `trim_px ≈ 8`, knot spacing >= 35, fit
  RMS/max sane, and minimum curvature radius > `thickness/2 * 1.05`;
* provenance (`reference_revision`, `reference_tree`, `config_sha256`,
  artifact `level_sha256`) and record/artifact seed equality;
* golden replay of all three fixtures: completion fields, every `result`
  field, and **byte-for-byte trace parity** plus the record's trace
  sha256/events.

Current result: **2,675 passed, 0 failed** (3 traces replayed byte-exactly).

## Known quirks

* **Colours are engine-assigned.** v3 does not reproduce the screenshot's
  colour layout. The source geometry's colour intent is blue 73 / green 1 /
  purple 0 / red 25, while the artifact's authored counts are blue 141 /
  green 1 / purple 0 / red 25 (25 red + 1 green + 27 blue circles, 114 blue
  annular). The engine's `PegColors.init` reassigns every peg from the
  seeded pool at `setupLevel`. There is no authored purple; the static
  artifact itself has `purple = 0`. Positions, shapes and counts are the
  contract.
* **Stale `trace.path`.** The Lua harness hard-codes
  `trace.path = "fixtures/traces/<id>.jsonl"` for every corpus, but the files
  actually live in `fixtures/ribbon_waves/traces/<id>.jsonl`. Read the corpus
  path; the record's `trace.sha256`/`trace.events` are authoritative. The
  Julia test asserts the stale string and then uses the real path.
* **Segments=16.** `Lines.generate` forwards the optional `peg.segments`
  override to `Peg.new_annular`; the ribbon pegs use 16 so the waves render
  smoothly. The default (4) and existing levels are unchanged.
* **No adaptive seam inset.** The v2 checker trimmed shared angular ends by
  up to 0.02 rad (mean 0.006758) to clear `LevelChecker` warnings. That
  inset is gone in v3: the level is five zero-gap `Lines.generate` lines,
  adjacent pegs share a full cap, and positions/radii are untouched.
* **Annular circle centres can be outside the board.** The arc itself is
  inside; only the centre of the arc's parent circle may be off-board. Do not
  bound annular `(x, y)` directly.
* **Line metadata is present and `slide` is awardable.** Every annular peg
  carries `line` metadata for one of the five open zero-gap lines, so the
  `slide` style is now awardable; the `ribbon_waves_ribbon` shot awards it
  (1 × 5,000 style points).
* **Structural mask residual.** Constant ribbon thickness, squared end caps
  and smooth-path/end-trim residuals account for most of the ~5.5%
  cleaned-mask loss; this is a model limit, not speckle noise, and is not
  tuned away.
* **`pieces` are legacy diagnostics.** The source geometry's 46 `pieces`
  (8/8/11/11/8) are per-brick seam/colour diagnostics from the v2 extraction,
  not the level's collision pieces. The exported level is generated from
  `ribbons[].path` into 114 annular pegs in 5 lines.

# Dev Log - 2026-07-05

## Progress Summary
- Designed and implemented scaling benchmarks to stress-test the custom deterministic physics engine and rendering.
- Built a suite of performance profiling tools (debug overlay and LuaJIT profiling).
- Upgraded the level-loading pipeline to fully support data-driven raw Lua tables for pegs, reinforcing our text-based level philosophy.

## Changes Made
- Created a Lua generator script to procedurally construct highly dense benchmark levels.
- Generated static benchmark levels with 100, 200, 300, 500, and 1000 pegs. These levels integrate a complex mix of grid-aligned static/sliding pegs and concentric rings of circularly moving pegs to guarantee intense collision scenarios.
- Integrated a real-time debug overlay in `main.lua` (toggled via `F3`), displaying:
  - Frames Per Second (FPS)
  - Memory Allocations (KB)
  - Average Frame Time (ms) to visualize physics/GC spikes.
- Added an `F4` keybind to toggle the dumping of LuaJIT profiling data (`jit.profile`) into `profile_dump.txt` for deep performance analysis.
- Added hot-swap keybinds (`F6` through `F10`) for instantly loading the various benchmark levels.
- **Bugfix:** Resolved a crash when loading raw peg data tables that lacked default properties (like `radius`). Updated `setupLevel` in `main.lua` to properly parse raw data files and initialize them via `Peg.new()` while cleanly preserving custom level-design properties (such as `circuit_id` for moving pegs).

## Next Steps
- Run the 500 and 1000 peg benchmarks and analyze the resulting `jit.profile` traces to identify bottlenecks in the custom physics resolution (e.g., collision sorting, CCD).
- Implement spatial partitioning or optimize vector math if physics scale poorly at extreme peg counts.
